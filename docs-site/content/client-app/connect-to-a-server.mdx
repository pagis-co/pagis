<Callout type="warn" title="Connect only to a server you trust">
When you connect to a server, this computer becomes a Host of that server.
The server and its Administrator can then run commands on this computer, with
the same access as you. They can also start a Coding Harness on this
computer, which runs as you. Connect only to a server whose Administrator you
trust.
</Callout>

## Set up the connection

"Connect to a Pagis server" shows the "Server address or sign-in link"
field. The setup page takes the address of the server, such as
`pagis.example.com`, or a [sign-in link](#connect-with-a-sign-in-link) of
the server, and nothing else: no email address and no password. It checks
the address before it sends it: an empty or malformed address gets a message
under the field, and the field takes the focus. The main process checks the
request again and refuses a request with no address in words for a person.
The client installs nothing, supervises nothing and keeps no key. It checks
that a Pagis server answers at the address and that its release is inside
the client's Compatibility Range: the client's own version and every later
version that promises the same API. When the server has no Administrator
yet, the client says so and names the Administration Interface that
finishes setup. Each of these problems shows under the field, and the setup
window stays. When the checks pass, the client keeps the origin in
`userData/server.json`, closes the setup window and opens the product
window. For an address, the window opens at the server's origin. There the
Product App shows its own sign-in page, and the Person signs in on it, as in
the Slack and Mattermost clients. When the cookie jar of the product window
holds a Session of the server, the client registers this machine as a Host
of the server.

## Connect with a sign-in link

An installation in Remote Access signs in a browser or an app on another
machine with a Sign-In Link, and never with a password
([ADR-0028](https://github.com/pagis-co/pagis/blob/main/docs/adr/0028-remote-access-runs-through-the-owners-tailscale.md)).
A link is an address of the server, `https://<host>/sign-in#<secret>`, and
it signs in one client, one time. Get a link in one of these ways:

- **From a browser or an app where you are signed in.** Under **Settings →
  Sessions**, select **Sign in another browser or app**, then copy the link.
  The link is good for five minutes.
- **From an Administrator.** An invite is a link for your first Session, and
  it is good for seven days. An Administrator makes a new invite with **New
  invite** under **People** in the Administration Interface.
- **With `pagis pair` on the machine of the server.** The command prints a
  link that is good for five minutes
  ([Sign-In Links](/server/sign-in#sign-in-links)).

Paste the whole link in the field, then select **Continue**. The client
checks the origin of the link as it checks an address: the https rule, the
health route, the Compatibility Range and the setup of the server. It keeps
the origin in `userData/server.json`, and nothing more. The secret of the
link goes to no file, no client storage and no log. The product window then
opens at the link. The page of the link posts the secret to the server, and
the answer puts the Session cookie in the cookie jar of the product window.
The client then registers this machine as a Host of the server, as after a
sign-in with a password. The Sessions list of the Person names the Session
"Pagis on macOS" or "Pagis on Linux".

A link with no secret, such as a copy that lost the part after `#`, gets a
message under the field, and the client sends nothing. A link that is spent
or expired opens a page that says so. The page names the three ways to a new
link, and it links to the sign-in page of the server. On an installation in
Remote Access, that sign-in page takes no password from this machine: it has
one field, **Paste a sign-in link**. Paste a new link there, also when the
client connected before and its Session ended.

## Start the Client App again

The client checks the range again on every start and refuses a server outside
it, with a message that says which end to update. The next start opens the
same server, signed in while the Session of the last sign-in lasts. When that
server does not answer, or its release is outside the range, the setup page
says so and offers "Try again" and "Choose another setup". It offers no
repair, because the client installed nothing. Quit stops no process, because
the client started none.

## Updates

A connected Client App follows the release of its server
([ADR-0027](https://github.com/pagis-co/pagis/blob/main/docs/adr/0027-the-client-app-installs-updates-and-upgrades-its-installation.md)).
Its Compatibility Range refuses a server older than itself, so it takes only
the Update to the release of its server, and never an Update past it. At
each check (at start, every 24 hours, and from "Check for Updates…"), it
reads the release of the server from the health route:

- When the server runs a newer release, the client downloads the Update to
  that release from the feed of that release on GitHub. It checks and
  installs that Update as in [Updates](/client-app/updates). So when the
  Administrator updates the server past the Compatibility Range, the check at
  the next start gets the Update that this client needs.
- When the server runs the same release or an older one, there is no Update.
  "Check for Updates…" says that Pagis is up to date with its server, and
  names both releases.
- When the server does not answer, the check fails and gives that reason.

The client prepares nothing for a restart, because it supervises no server.
"Restart to Update" asks no question about Runs, because the Runs belong to
the server.

## Only over https

**The client connects to a server only over `https://`.** It refuses an
`http://` address before it sends a request, unless the host is loopback
(`127.0.0.1`, `[::1]` or `localhost`), such as an SSH tunnel. The refusal
names the two ways to an `https://` address: Remote Access on a local
installation ([Serve several People](/client-app/several-people)), and a proxy
that holds TLS in front of a server. A `server.json` that holds an
`http://` origin of another computer fails at the start, and the setup page
shows the refusal. The client follows no redirect before the product window
opens, and uses the TLS certificate check of the platform. On an `https://`
origin, its cookie jar holds the Session cookie as `Secure`, also where the
server set it without `Secure` ([ADR-0024](https://github.com/pagis-co/pagis/blob/main/docs/adr/0024-a-server-serves-a-network.md)).

## The trust of a connection

When you connect to a server, this computer becomes a Host of that server.
The server and its Administrator can then run commands on this computer, with
the same access as you. Under "Connect to a Pagis server", the setup page states this in
one line under the Server address field: "Connect only to a server you
trust." The client registers as a Host of the
signed-in Person and runs every `dispatch` frame the server sends, as the OS
user who started it. The approval, the effect class, the allow rules for each
machine and the audit row all live on the server, and the client applies no
check of its own, on purpose: a second confirmation here would ask a question
the server's approval card already asked, and it would not change the trust.
So a person who takes control of the server can also run commands on this
computer ([ADR-0015](https://github.com/pagis-co/pagis/blob/main/docs/adr/0015-a-host-action-runs-on-a-present-client.md)). The client trusts the server that TLS authenticates, and
it registers as a Host on no clear-text connection to another machine.

The server and its Administrator can also start a Coding Harness, such as
Claude Code, on this computer. The client starts the program that the server
names, in the directory that the server names, as the OS user who started
the client, and copies the bytes of the program to the server and back. The
client applies no check of its own here either. A Client App of a local
installation starts a Coding Harness for its own server in the same way
([ADR-0033](https://github.com/pagis-co/pagis/blob/main/docs/adr/0033-a-coding-session-is-a-guest-coding-harness-that-an-agent-supervises-over-acp.md)).
